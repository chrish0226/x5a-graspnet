# SAM 腕部工程说明

当前配置以 `config/sam_grasp.yaml` 和 `src/x5a_pick_place/launch/wrist_sam.launch.py` 为准。安装、启动和常用指令见[根目录 README](../README.md)。本文说明当前实现，不保留已回退方案的启用说明。

## 感知与坐标契约

- 输入为 Gemini 对齐的 1920×1080 RGB-D；可靠订阅，RGB/深度配对误差最多 40 ms，深度原始单位按 0.001 m 转换。
- 图像使用 `wrist_camera_color_optical_frame`，以曝光时刻 TF 转到 `wrist_preview/base_link`；工具帧为 `wrist_preview/tool0`。
- 先调用 `/v1/locate` 获取同一帧 SAM 掩码，在本机剔除桌面以下、臂展外和不连贯的异常目标深度，再把清理后的掩码交给 `/v1/grasp`。后者跳过重复 SAM，掩码膨胀为 0，避免重新混入背景。
- 当前上传 RGB 使用 quality=95 的 JPEG；深度和掩码仍为无损格式。接触验证使用观测点，不把几何补全面当成真实观测接触点。
- 小方块只看见顶面时，可依据可信的约 20–55 mm 方形尺寸补全放置几何，底面受桌面限制。它用于持物/放置推算，不代表看见了隐藏表面。

可在已有相机/TF 节点运行时只读检查，不发送运动或请求路径规划：

```bash
source scripts/env.bash
/usr/bin/python3 scripts/check_sam.py
# 同一终端先加载自己的 SAM_GRASPNET_API_KEY，再测试真实推理：
/usr/bin/python3 scripts/check_sam.py --prompt 'red cube'
```

检查输出在 `reports/sam-integration/latest_check.json`，抓帧在 `capture.directory`。这些运行数据默认不提交 Git。

## 规划阶段

| 任务 | 阶段 |
| --- | --- |
| 单抓 | PREGRASP → GRASP → LIFT → RETREAT |
| 整句抓放 | PREGRASP → GRASP → LIFT → TRANSPORT → PLACE → RETREAT |
| 已持物放置 | TRANSPORT → PLACE → RETREAT |
| 空手重新观察 | OBSERVE；成功后从新 RGB-D 重新规划原任务 |

同一个抓放任务在开始运动前完成全部阶段规划。队列中的下一任务待上一步完成、回到可观察状态后重新采图和规划。当前没有在每一段运动后都重新观察，也没有持物纯放置的自动靠近重规划。

GraspNet 候选先做开口、目标支持、接近和场景几何筛选，再进入 IK / 路径规划；必要时尝试经相同检查的几何候选。低位备用姿态优先顺序目前是 pitch `[0.5, 0.6, 0.75, 0.9, 1.15, 1.45]` rad；最近成功方向只用于排序，不能代替新场景的检查。

全局段使用碰撞感知 IK 和 OMPL RRTConnect。GRASP / PLACE 需要完整笛卡尔路径（完成比例至少 0.9999）与终点 FK 核对。PREGRASP/GRASP/LIFT 前缀失败后不重复尝试只改变放置参数的同一前缀；同次观测中缓存前缀结果，新观测不复用旧碰撞结论。

默认 TRAC-IK Speed，4 个独立 worker 使用当前 MoveIt 的同一份标定模型。可在直接 launch 时使用 `ik_solver:=kdl` 比较；Pilz / CHOMP 已列入加载配置，但不应未经同场景验证就宣称比默认规划器更快或更可靠。

## 8 秒预算与重新观察

`planning.total_budget_s: 8.0` 控制候选搜索。采图、解析、远程推理与机器人执行另计，阻塞调用也可能使总墙钟时间超过预算，因此它不是整条指令的 8 秒硬超时。

仅当空手抓取耗尽规划预算、已确认空手、目标深度/可见性有效，且额外 2 秒预算内找到完整碰撞检查的观察路径时，才允许靠近约 3–6 cm，随后重新取图并规划一次。最多一次重试。没有路径、未耗尽预算而是候选提前用尽、正在持物或纯放置时，不执行该恢复。

失败计划中的一部分不会被直接拿去运动。OBSERVE 是独立规划并验证的完整短路径。

## 桌面与夹爪

桌面保持测量位置，仅允许两根夹指 `wrist_preview/link7` / `link8` 进入 5 mm 模型不确定带，另设下方限制体。夹爪本体、腕部、相机及其余连杆仍检查桌面碰撞。

当前共享夹爪实验关闭：`gripper.model_path: ""`。活动配置沿用原生映射、15 mm 抓取参考、100 mm 简化手指长度及原厂 URDF/STL 碰撞网格；测量版 JSON 和扩展网格只是保留的实验资源，见[模型说明](../models/README.md)。

## 放置对齐与换面

支撑面使用凸包中心，放置考虑实际持物偏移，按候选旋转重新计算物体底面。叠放优先中心对齐，中心横移约束在 3 mm，避免为了可达而偏移数厘米。当前释放间隙尝试 10/15/18/20 mm，搬运余量 80 mm。

方块边方向由顶面的最小面积矩形估计，避免正方形 PCA 主轴不稳定。原先仅允许保持原顶面朝上；现在 `grasp.allow_cube_face_change: true` 对可信小立方体枚举 24 种等价面/边旋转，允许另一面朝下。要求边长约 20–55 mm、XY 比例不超过 1.15、高度/平面边长比例在 0.80–1.20；薄板、细长物体、明显长方体和大物体不适用。

每个候选重新规划 TRANSPORT / PLACE / RETREAT。浅角抓取可能使某些放置方向不可达，但不能仅因保持原顶面朝上的候选失败，就断言当前夹持没有任何可放姿态。换面仍可能因桌面、本体或支撑物碰撞而失败。

## 执行、反馈与持物

`grasp.pre_execution_visual_recheck: false`：静态桌面任务不在执行前再次采图调用 SAM，使用已规划观测。保留轨迹指纹、最大采图到执行时效 60 s、反馈新鲜度、驱动健康及任务/持物状态检查。物体移动后应重新下发任务。

额外 TCP 精度检查为提示；底层标准到位阈值 0.02 rad，在有真实运动响应、稳定且残差不超过 0.06 rad 时允许按宽容规则继续。更大偏差、失联、跟踪异常、硬关节范围和速度限制仍可阻止执行。

松爪使用约 0.65 s 平滑打开，再保持/验证约 0.8 s。打开时维持最近下发的机械臂目标，避免把测量抖动重新写成关节目标。持物判断仍主要依赖开度与反馈，没有力传感或最终摆放视觉闭环。

持物状态包含工具到物体的关系，主要保存在执行器内存。不要在持物时随意重启执行器；新进程不能自动推断之前的抓姿。当前 SAM 持物点云没有完整作为附着碰撞体覆盖所有运动阶段。

## 多步骤指令与日志

支持“然后 / 接着 / 随后 / 之后 / 再把 / then”等明确分隔符，最多 8 步；各步独立解析，共享一个任务所有权锁。取消跨步骤保持有效，任一步失败或未确认释放就停止队列。

正常终端给出任务号、步骤、阶段、耗时和持物状态。底层错误会保留 Action 的 `error_message`，取消与失败区分，`--verbose` 可展开 MoveIt 细节。颜色检测每秒输出的 `MULTI DETECTION` 已改为 DEBUG。

## 常见失败的定位顺序

| 表现 | 先检查 |
| --- | --- |
| SAM 404 / 没找到目标 | 指令解析后的英文提示词、box/cube、颜色与掩码；不要先增加规划时间 |
| 目标有坐标却被过滤 | 工作空间和 `r_max`，例如 `(0.398, 0.470)` 的半径约 0.616 m，超出当前 0.54 m |
| 深度点不足 / 异常 | 原始掩码、有效前景、桌面/臂展裁剪、RGB-D 同步和曝光 TF |
| PREGRASP IK 失败 | TCP 目标、种子、关节范围、手腕及相机碰撞 |
| GRASP / PLACE 比例不足 | 直线沿途碰撞、终点 FK、夹指/本体碰桌；有终点 IK 不代表整条直线可走 |
| TRANSPORT 失败 | 当前夹持下的搬运/放置姿态、全局路径与桌面/支撑物碰撞 |
| 计划成功后执行中止 | 原始适配器错误、实际运动、反馈新鲜度、电机健康与持物状态 |
| 叠放偏差 | 标定、持物偏移、缺底面的几何估计、控制到位误差和松爪后滑落 |

最新离线证据与尚未验证的部分见[验证记录](VALIDATION.md)。模型推理、路径规划、控制器到位、成功夹持、成功摆放是不同验收项。
