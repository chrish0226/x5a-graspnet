# 本地颜色方块流程

这是独立于 SAM 的腕部颜色流程，使用同一 Gemini、标定候选、驱动与 MoveIt 适配器。启动与构建准备见[主 README](../README.md)。

```bash
bash scripts/start.sh
# 仅测试交互，不启动机械臂/相机，不做路径规划：
bash scripts/start.sh --dry-run
# 已启动时，另一个终端输入：
bash scripts/text.sh
```

网页 HTTP 8001 / HTTPS 8444，同时提供 8000 / 8443 兼容入口。它与 SAM 使用同一进程锁，不能同时运行。语音默认本地 SenseVoice，规则解析在本机完成。

这套流程的图像检测、中文规则解析和路径规划均可在机械臂主机本地运行，不依赖 SAM / GraspNet / Ollama 云端服务。语音需要先下载本地 ASR 模型；纯文字操作可跳过语音模型安装。颜色识别仍使用 RGB-D 中的深度定位，并不是只有 RGB 的二维抓取。

它与 SAM 共存于当前工作区；原主机 `backups/` 中还有颜色识别和场景记忆修改前的历史副本。这些本机备份未上传，保留的是上表所列当前源码和配置。

支持红、白、橙方块、盒沿、完整抓放、先抓后放、当前侧/镜像侧准备、遮挡清理和当前进程内叠放记忆。自动暂放使用当前 RGB-D 观察到的可用区域，配置在 `config/buffer.yaml`；固定暂放模式需另行配置。

```text
准备
抓红色方块
放到白色方块上
把红色方块放进盒子里
```

主要配置：

| 文件 | 用途 |
| --- | --- |
| `config/vision.yaml` | 颜色阈值、目标尺寸、同步、顶面与盒沿 |
| `config/task_plan.yaml` / `task_execute.yaml` | 阶段、规划、执行与场景策略 |
| `config/buffer.yaml` | 自动/固定暂放 |
| `src/x5a_task_server/.../wrist_task_server.py` | 任务、遮挡与状态管理 |

当前演示配置关闭场景方块、支撑方块和盒沿的环境碰撞模型（`wrist.scene_objects_collision_enabled: false`、`box.collision.enabled: false`）；桌面和自身碰撞仍参与检查。它降低了局部场景建模覆盖，不能据此宣称完整杂物避障。

叠放记忆只在当前服务运行期间有效，最长一小时；不跨观察坐标系使用，重启清空，不会自动纳入人工堆叠或旧历史动作。单帧异常不直接清空关系，但也不允许使用不匹配记忆。

自动候选可达不等于完整路径通过；运动中执行失败会结束任务。检测与标定同样受原实验模型精度限制。以上功能不可直接推断为 SAM 已支持。

## 2026-10-20 速度与容差优化

当前颜色配置采用以下参数，真实整轮耗时仍需在实机重复测量：

| 项目 | 修改前 | 当前 |
| --- | --- | --- |
| 接近 / 放置速度、加速度缩放 | 0.33 / 0.19 | 0.45 / 0.25 |
| 抬升 / 撤离速度、加速度缩放 | 0.40 / 0.24 | 0.55 / 0.32 |
| 搬运缩放 | 0.82 / 0.43 | 保持 |
| 每次全局规划请求时间 / 尝试数 | 5 s / 6 | 3 s / 4；不是整条任务硬超时 |
| 预抓取候选 | 先收集最多 3 个再尝试搬运 | 每次检查 1 个，完整接近通过后立即尝试；仅规划失败才继续下一个 |
| 观察位到位容差 | 0.03 rad | 0.06 rad，与控制器普通到位策略匹配 |
| 反馈边界残差 | 严格 | 最多 0.015 rad 为提示；规划轨迹依旧严格检查关节范围 |

`wrist.table_collision_offset_m: -0.005` 仅把 MoveIt 中的 table / table_mirror 碰撞体下移 5 mm。`table.z` 和视觉桌面高度保持原值，防止把碰撞余量混入方块高度、叠放和盒沿计算。这个余量也不代表实体桌面变低了。

`vision.reobserve.enabled: false` 保持关闭，抓前不会因为二次视觉位置变化触发纠偏停止。执行时使用新鲜实际关节反馈作为规划起点，减少虚拟终点缓存引起的起点偏差；仅规划模式仍使用连续的虚拟终点。

这些设置没有关闭硬关节范围、命令轨迹边界、完整笛卡尔路径、反馈过期、跟踪异常、电机保护或持物检查。真实越界 / 失联依旧停止任务。恢复通信也不会自动续跑旧任务。

## 新增口语与交互

| 说法示例 | 处理方式 |
| --- | --- |
| 请你帮我夹起红色小方块 / 拿起来橘色的那个小积木 | 单抓，返回观察位等待放置 |
| 把红块放白块上 / 把白色叠橙色上面 | 同一句抓取并叠放，仍受两层几何约束 |
| 先抓红块，然后放到白块上 | 合并为一个明确的红 → 白抓放任务 |
| 把它放白色的小方块上 / 把手里的方块收进收纳盒里 | 放置当前持物 |
| 把这三个小方块都收进盒子里 | 依次红 → 白 → 橙；单个 ROS 队列保持所有权 |
| 按橙白红顺序放进盒子 | 按明确颜色顺序收纳 |
| 把白色放进盒子，然后把橘色放进盒子 | 合并为同一个批量收纳队列 |
| 你拿着什么颜色 / 看到了哪些方块 / 当前状态 | 只读查询，可在任务忙时使用 |
| 帮助 / 支持什么指令 | 显示语音示例，不要求机械臂服务就绪 |
| 别拿白块 / 不要放白块上 / 停止 | 取消优先，不执行同句其他动作 |

“橙 / 橘 / 桔”、小方块 / 积木 / 正方体 / 立方体 / 木块及常见礼貌前缀可识别。重复颜色、数量与颜色不一致、未知颜色、没有放置目标的连续抓取、未支持的多步叠塔会整体拒绝，不只执行前半句。当前没有实现“把三个叠成三层”的自动策略。

网页增加识别情况、持物颜色和语音示例入口；Android 仍通过同一服务端解析受益，不需要为了这些语法更新 APK。

## 叠放四方向候选修复

此前颜色叠放只选择与当前夹持旋转最小的一个棱角对齐朝向。该朝向不可达时，KDL 逆解和 MoveIt Pose Goal 均可能失败，尽管另一个相差 90° 的朝向能用。

整句叠放和抓起后另行指定放置现在都枚举 4 个保持原顶面朝上的等价对齐方向，按工具转动量排序，依次进行：

1. 按各自旋转重新计算工具到物体的夹持偏移，保持物体中心在支撑方块中心。
2. 计算预放置位的碰撞感知 IK，检查完整下降路径及严格关节范围。
3. 仅通过前两项后才尝试搬运；搬运规划失败可继续下一个方向，执行中断立即结束任务。
4. 选择后使用该方向对应的 TCP 执行下降；全部失败则保持夹持，不松爪。

这四方向是方块绕桌面法向的 90° 等价旋转，不是任意倾斜或换底面，也没有增加叠塔层数。仍保持中心对齐，不用横移支撑位置来换取可达性。

IK、全局规划和笛卡尔请求中的部分关节起点显式使用 `RobotState.is_diff=true`，保留当前场景的持物附着碰撞体；MoveIt 对非 diff 的完整状态会清空旧附着体，见[官方转换实现](https://github.com/moveit/moveit2/blob/humble/moveit_core/robot_state/src/conversions.cpp)。

2026-10-20 只读回放使用保存的白块目标、相同橙块持物几何与当时活动的 MoveIt 场景。原约 130.4° 朝向失败后，第二个约 40.4° 朝向通过：搬运规划返回 33 个轨迹点，下降完成率 100%，候选搜索与规划本次约 0.36 s。请求 `plan_only=true`，没有调用轨迹执行、夹爪或场景更新。它验证搬运和下降，不等于已实机松爪放稳或验证撤离。

回放原始结果保存在本机 `reports/color-place-failure-20261020/fixed_search_replay.json`，不上传运行快照。当前持物进程没有重启，构建后需下次正常启动加载新逻辑。
