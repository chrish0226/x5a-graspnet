# 抓取停在顶面的回归修复（2026-10-03）

本记录纠正上一轮 `place_contact_20261003` 将 CAD 指尖距离作为实机抓取偏移的错误。
此前物体确实抓取成功，因此恢复有实机成功记录的配置，而非继续猜测新的偏移。

## 回归证据

失败快照 `20261003_163107_150215`，现场画面 `20261003_163221_768940`：
手指合拢但红块留在桌面，用户观察到夹爪末端只到红块顶面。执行器报告
`夹爪闭合后未确认持物: empty`，没有进入 LIFT。

原工具目标高度 68.44mm。上一轮将 15mm 改成 44.8mm；同一抓取参考点和
近竖直朝向下，该变更会把工具目标抬高约 29.58mm。CAD 网格中的尺寸不能证明
实物安装、TCP、相机外参及 GraspNet 抓取参考点之间的标定已正确。只规划通过
和模型接触位置检查不足以证明实际接触深度，这是先前结论的限制。

## 修复

- 恢复 `grasp.tip_offset_m=0.015`、`tcp_backoff_m=0.015`、
  `transform_grasp_tool_translation=[-0.015, 0, 0]`。
  这些值作为此前实机有效的抓取参考模型保留，不能称为已量测的物理指尖距离。
- 保留支撑物碰撞实体、抓取后闭合手指状态、松爪前 TCP 复核，以及
  实际夹持几何计算放置点的改进。不以放宽失败判定掩盖空抓。
- 修复支撑物清理的重复删除问题：先查询 MoveIt 场景，只删除仍存在的
  支撑实体。删除已不存在的对象会使 MoveIt 报 scene apply failed，
  该缺陷会阻止后续纯抓取规划。
- 更新配置说明和回归测试，明确区分 CAD 尺寸与实机有效抓取参考偏移。

## 验证

63 项相关测试通过，新增支撑实体存在/不存在时的重复清理测试。
此次失败图像用 `scripts/validate_grasp_regression.py` 做隔离命名空间回放，
没有使用控制器动作或执行服务。从模拟 READY 开始，四段抓取规划通过（约1.4s）；
选中工具高度为 44.08mm，比失败高度低24.37mm，接近此前抓取成功时约44mm的高度。
回放见 `20261003_163107_150215/replay.json`。

这只是抓取规划恢复验证，不是修复后实机抓取成功证明。碰撞模型与实机安装仍需
进一步校准；如果当前夹持几何无法避开支撑块，放置应该明确失败，不强行下降。
本轮只更新规划服务，未控制机械臂/夹爪，执行器及持物状态保留。
