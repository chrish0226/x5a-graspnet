# 白块下降停止：指尖模型与支撑物碰撞（2026-10-03）

> 后续实机验证发现 44.8mm 抓取偏移导致空抓，已恢复 15mm 的有效抓取参考。
> 本记录的 CAD 参数替换结论已被纠正，见 `../grasp_reference_regression_20261003/FIXES.md`。


抓取快照 `20261003_160859_754402`，放置快照 `20261003_160928_915199`。
查看停下时的实时 RGB-D 快照 `20261003_161116_293353`：红块仍在夹爪中，

## 证据

- 执行器的直接停止原因：`实际放置点误差 8.2mm/1.3度，未松爪`。
  官方轨迹适配器先以关节最大误差 0.0169rad 报告到达，后续 TCP 检查拒绝松爪。
  这不是已确认的力控触底信号；代码没有将碰撞解释为放置成功。
- 目标 tool0 `[0.22339, 0.30175, 0.07303]` m，停下时新鲜 TF
  `[0.22473, 0.30322, 0.08088]` m：主要差在高度约 7.85mm，XY 约 2mm。
- `/move_group/get_parameters` 的实际 robot_description 与本地 URDF 相符：
  joint7/8 在 link6 的 X 偏移 86.57mm，tool0 偏移 112.77mm；厂商 STL
  指尖的局部 X 为 71mm。因此模型中的 tool0 到指尖偏移为 44.8mm，
  不是原来的 15mm。尚未进行独立物理量测校准。
- 放置场景原来只有桌面和相机，没有白色支撑方块。碰撞规划可以接受
  手指进入白块的位置。加入支撑面实体后，同一旧释放关节状态被 MoveIt
  判为碰撞（2 个接触）：link7 与支撑体相交约 1.40mm，link8 也有接触，
  详见 `old_goal_collision.json` 和 `contact_replay.json`。
- 部分 IK 种子只提供六个手臂关节却标记成完整状态，且组合抓放规划未在
  GRASP 后模拟闭合的手指。二者会造成规划时的夹爪形状与真实持物状态不同。

## 修复

- 本地机器人配置的指尖偏移、GraspNet 到 tool0 的平移和模板后退量统一改为
  按当前 URDF/STL 得到的 44.8mm。重新抓取时指尖实际接触位置与几何检查一致，
  不再把 29.8mm 的几何差异留给真实机器人。
- 支撑面凸多边形生成闭合实体网格，横向保守外扩至少 2mm，加入 MoveIt 碰撞
  场景；新任务无支撑面时明确删除旧障碍，避免旧放置目标挡住下一次抓取。
- 六关节 IK 种子标为增量状态，保留当前手指位置。组合抓放在 GRASP 后按
  目标总夹持宽度的一半设置 joint7/8，在 PLACE 后按打开位置设置手指，
  使后续轨迹按对应夹爪形状检查碰撞。
- 保留严格 TCP 松爪检查，不提高误差阈值或把失败当成已触底。无法无碰撞放置
  时提示重新抓取，让物体底部伸出指尖。
- 移除执行函数文档中已经不适用的“跟踪保护可作为触底信号”描述。
