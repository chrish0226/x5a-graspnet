# 腕部电机反馈与保护恢复修复

修复位于独立包 `x5a_wrist_driver`。原厂 SDK 文件、原厂驱动和原 `arm` 工作区未修改。它只支持本机已检查的 x86_64 SDK，构建和启动都校验 SHA-256；换 SDK 后会拒绝启动，避免误用内部布局。

SDK 未提供电机实现源码或掉线阈值参数，因此此包使用独立兼容层修正已确认的在线判定和总在线标记。原 SDK 的反馈解析、CAN 收发、控制增益、电流/电机故障保护继续使用。兼容层仅被这个驱动进程加载。

## 行为

- 电机 CAN id 1、2、4（SDK 报警关节编号 1、2、3）的反馈超时从 100ms 调整为 300ms。其它电机保留原来的 800ms 阈值。配置在 `config/driver.yaml`；前者限制在 100–500ms，后者限制在 200–800ms。
- 用接收回调记录的单调时间计算新鲜度，避免系统校时影响掉线判断。收到其它电机的帧不会延长本电机的有效期。
- 收到有效反馈后，电机和整臂在线标记可以恢复。没有反馈、超过阈值、电流/电机故障仍会保护。
- 实际进入保护会把 SDK 控制模式留在 PROTECT，同时锁住新指令。恢复通信不会恢复原来的运动模式或旧目标。
- `/arm/health` 提供各路反馈年龄、是否在线、是否保护、是否可以接受指令、原 SDK 错误码。适配器和任务服务检查该消息，避免把新发布的缓存关节值当成电机健康证据。
- 取消旧任务后说“准备”，任务服务调用 `/arm/recover`。复位要求反馈连续健康至少 500ms，并且旧命令已停止至少 500ms。复位服务只解锁指令入口，不发送位置/夹爪动作；随后准备任务从当前姿态重新规划到观察位。
- 正常完成一次抓取无需再次准备。仅真正进入保护后需要明确复位；普通抓取指令不能清除保护。

## 切换

当前旧驱动不会被自动替换。切换前先将机械臂放在有支撑的位置，停止手机任务并确认空闲，关闭运行 `open_single_arm.launch.py` 的旧驱动终端。关闭驱动和重新使能可能改变机械臂受力。

启动独立驱动：

```bash
bash /home/quella/arx/wrist_ws/scripts/start_driver.sh
```

该脚本会拒绝与已有驱动同时运行；不杀旧进程、不自动执行准备或回零。腕部整套启动也已改为在需要启动驱动时使用这个包。重复驱动仍禁止。

现有任务/适配器进程需要在空闲时切换到本工作区的新版本，才能使用新的健康显示和“准备”复位。它们的源码已经改好；正在运行的旧进程不会因构建自动加载新代码。

回滚时停止新驱动，再使用原厂的 `open_single_arm.launch.py`。原厂二进制和配置无需恢复。

## 验证范围

已用原厂 SDK 的真实反馈解析函数离线重放验证短暂延迟、真实超时与在线恢复；测试不创建 SDK 控制接口、不打开 CAN、不发送动作。策略测试检查恢复需要稳定反馈和旧指令停止。另有适配器健康消息/腕部任务回归测试。

上线后仍需先观察空闲反馈与保护状态，再由用户发起“准备”和低速小范围动作确认。首次触发超时的物理/调度原因尚未捕获，本修复没有宣称消除供电、连接线或驱动器自身故障。
