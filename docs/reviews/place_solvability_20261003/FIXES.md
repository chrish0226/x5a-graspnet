# 白块/橙块连续放置规划失败（2026-10-03）

此次日志显示红块抓取已成功（16:40:48，夹爪 gap 已确认，LIFT/RETREAT 完成）。
失败的是两次独立放置：白块快照 `20261003_164100_000967`、
橙块快照 `20261003_164147_521557`。旧规划下降段只达到约 94%~95%，
没有发布可执行规划，执行器仍持物；没有在这两次放置中实际移动手臂。

## 原因与修改

- 上一轮将支撑物加入碰撞场景后，固定的 2mm 物体底面间隙不足以让本次
  夹持位置的手指避开支撑块。仅要求这一个释放高度降低了实际可解性。
- 改为依次尝试 2/5/8/11mm 的小幅竖直释放间隙，配置上限不超过12mm。
  每个高度仍必须完成全程碰撞检查、完整直线下降、终点 FK 检查。
  物体底面和支撑面中心保持对齐，优先选择最小可解间隙。松爪后物体会有
  几毫米的下落，不能把目标间隙视作真实落点精度。
- 回放显示白块释放高度8mm可解；橙块下降也可解，但原来一直保持释放朝向
  并抬高80mm的撤退目标没有 IK 解。该撤退姿态是前次放置修复引入的可解性回归。
- 撤退改为保持释放朝向竖直上移30mm，再用 MoveIt 无碰撞路径转到原来的
  transit 姿态和撤退高度。两条轨迹合并为同一个 RETREAT 段，段数与执行器
  契约不变；连接点必须连续，时间严格递增。竖直离开段同样必须100%完成，
  并通过 FK 校验，不能用任意关节路径替代失败的离开段。
- 选中放置记录增加 `observed_bottom_clearance_m`，便于核对实际使用的释放间隙。

本轮没有改变15mm抓取参考偏移、抓取候选、实际持物记录或松爪前3mm TCP误差检查。
不接受部分下降轨迹、不把碰撞当触底成功、不自动开夹爪。

## 验证

65项相关测试通过，包括最低无碰撞释放高度搜索、保持中心对齐、合并撤退轨迹

`scripts/validate_place_solvability.py` 用两次原始点云、实际抓取时保存的持物几何、

最终记录见 `replay.json`：两例三段 TRANSPORT/PLACE/RETREAT 均通过，
都选择8mm释放间隙，分别约1.39s、1.38s。先前固定高度与纯竖直高处撤退不能通过。

本轮只更新规划服务，不重启执行器，保留当前持物几何以支持直接重规划放置。
尚未执行修正后的实机放置，仍需确认夹持偏移、标定误差和松爪后的落稳情况。
