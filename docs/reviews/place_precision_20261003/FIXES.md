# 红色方块放置偏差修复（2026-10-03）

实际失败任务：抓取快照 `20261003_154105_469549`，放置快照
`20261003_154136_413750`。执行器没有报轨迹失败，但物体未放稳。

## 日志与点云证据

- 原目标把整个方块点云的包围中心作为 tool0 的 XY，并把方块顶高加
  固定 25mm 作为 tool0 的 Z，没有使用被抓物体相对于工具的几何位置。
- 原记录中心 XY 为 `[0.10158, 0.32888]` m；同一图像重新分割后取顶面多边形
  中心得到 `[0.11053, 0.32593]` m，差约 9.4mm。侧面点云导致了偏心。
- 按原抓取点云和原放置朝向估计，物体底面 p5 高度 26.81mm，原记录
  红色方块顶面为 36.12mm，约低 9.31mm。该值是几何回算，不是实测穿透。
- 原 PLACE 目标关节与下一段开始时记录的实际关节经 `/compute_fk` 回算，
  TCP 相差约 3.09mm。关节记录已四舍五入，且实际值采样在松爪之后，
  因此不能当作松爪瞬间的精确测量。

## 修改

- `place_geometry.py`：把抓取对象点云转到实际抓取 tool0 坐标系。每个释放
  姿态重新旋转点云，按 p2/p98 包围中心补偿 XY，并按底面高度补偿 Z，
  使观察到的物体底面位于支撑面上方 2mm；移除固定物体半高参数。
- 放到方块「上」时取顶面多边形中心，落点离边缘至少 4mm。原有偏移搜索
  不得越出有效支撑面。优先保持抓取朝向，或仅绕基座 Z 轴旋转；拒绝
  倾斜物体超过约 4.6 度的放置姿态。松爪后先保持朝向垂直撤离。
- 执行前的感知复核返回对象点云、抓取 TCP 和释放 TCP，绑定轨迹指纹。
  执行器在实际到达抓取点时记录 tool0，并在确认持物后保存夹持几何。
  后续独立放置从执行器读取该几何，不使用上次「规划成功」冒充抓取完成。
- 放置执行前复核支撑面，变化超过 3mm 必须重规划。组合抓放分别复核
  被抓物体和支撑物。
- 松爪前用新鲜 TF 检查实际 tool0：位置误差不超过 3mm，角度不超过
  0.05rad，允许最多 1 秒收敛。检查失败保留夹持，不松爪。组合抓放计划
  的实际抓取位姿同样使用更严格的误差上限，约束预测夹持几何的误差。
- 执行完成文字改成「放置轨迹执行完成，夹爪已松开」，不宣称已视觉确认放稳。
- 新增放置点云、定位响应、选中放置 TCP 和抓取指纹的诊断记录。

## 实机验证与限制

尚未执行修正后的实机放置。单帧 RGB-D 只能看到部分物体表面，底面估计、
相机标定、夹持滑动和执行误差仍可能影响实际结果；2mm 是规划几何间隙，
不是承诺的真实落点精度。当前没有放置后的视觉稳定性确认。
应重新抓取后再发放置指令，以取得实际夹持几何。重启执行器会丢失持物几何，
因此本次只在执行器空闲且报告未持物时更新服务。
